MAJOR CHANGES
=============

## [0.4.1.0] - 2026-10-10

### API Authentication, Authorization & Rate Limiting

- Added ApiCallerMiddleware in microservices/HalfQR.PublicApi/Security/ApiCallerMiddleware.cs supporting Authorization: Bearer <token> (for hqr_sk_ API keys and hqr_pat_ access tokens) and X-Api-Key headers.
- Integrated CredentialVerifier to validate incoming credentials against HalfQR.Identity via HTTP POST /internal/v1/credentials/verify with internal secret authentication.
- Implemented RequireApiScope endpoint route filter in PublicApi enforcing granular scopes ApiScopes.QrRender (qr:render) on render and draft endpoints and ApiScopes.QrRead (qr:read) on job status and artifact downloads.
- Added partitioned rate limiting via builder.Services.AddRateLimiter(...) in PublicApi with dedicated policies: 'render' (anonymous quota vs. subscriber plan limit), 'draft' (anonymous draft quota), and 'read' (read operations).
- Implemented secure caller IP partitioning in ApiCallerMiddleware: extracts client addresses from X-Forwarded-For only when validated against a shared HALFQR_PROXY_SECRET header, preventing address spoofing.
- Bound render jobs to creator credentials via RenderJobState.OwnerCredentialId; enforced private job isolation in RenderJobService.GetStatusAsync and GetArtifactAsync, returning HTTP 404 to unauthorized callers to prevent job GUID enumeration.
- Sanitized queue failure responses in RenderJobService: replaced exposed internal exception messages with generic user messages ('The render queue is unavailable. Please retry shortly.') while logging detailed exceptions on the server.
- Added strict security headers on all PublicApi responses (X-Content-Type-Options: nosniff, Referrer-Policy: no-referrer, HSTS on HTTPS) and applied sandbox Content-Security-Policy ('default-src 'none'; img-src data:; style-src 'unsafe-inline'; sandbox') to SVG artifact downloads.

### QrEngine Sanitization, Hardening & Validation

- Hardened SVG logo XML parsing in microservices/HalfQR.QrEngine/Rendering/QrLogoProcessor.cs: replaced plain XDocument.Parse with ParseSvgDocument using XmlReaderSettings with DtdProcessing.Prohibit and null XmlResolver to eliminate XML External Entity (XXE) vectors.
- Enforced strict SVG complexity caps: limited total SVG element count to 4,000 and <use> elements to 64; implemented ValidateUseReferences to detect and reject nested <use> reference chains that could trigger quadratic amplification in SkiaSharp rasterization.
- Expanded CSS URL sanitization: updated ContainsUnsafeCssUrl validation across all element attribute values, blocking url() injections through SVG presentation attributes (fill, stroke, mask, clip-path, filter).
- Prevented raster logo decompression bombs in QrLogoProcessor.EnsureDecodableRasterSize: inspects dimensions via SKCodec.Create prior to decoding full pixel buffers, capping decoded size at 4096 x 4096 pixels (16 megapixels) and 512 KB payload size.
- Hardened QrRenderRequestValidator.cs: added ValidateEnums using Enum.IsDefined across ContentType, Mode, ErrorCorrectionLevel, Finder.BorderShape, Finder.CenterShape, Data.Pattern, Data.GradientMode, and Logo.SourceType to reject raw integer bypasses.
- Added ValidatePayloadShape in QrRenderRequestValidator: capped TargetUrl to 2,048 characters, payload dictionary entries to 16, key lengths to 64 characters, and value lengths to 2,048 characters.
- Added validation rejection for QrRenderMode.Managed, returning an explicit HTTP 400 validation error informing clients that dynamic managed QR codes are not yet available.
- Refactored SVG composer modules (QrSvgComposer.cs and QrFinderSvgComposer.cs): centralized QuietZoneModules (4) and FinderSizeModules (7) constants, introduced IsInFinderSpan helper, and extracted shared SvgNumberFormat.Format(double) to eliminate duplicate invariant floating-point formatting.

### HalfQR.Identity Service (Auth, Sessions & Credentials)

- Implemented microservice in microservices/HalfQR.Identity targeting .NET 10 with pluggable FileSystemIdentityStore and PostgresIdentityStore storage backends.
- Created PostgreSQL schema 'identity' with automatic startup initialization for users, sessions, api_credentials, and email_verifications tables with JSONB document records and indexed lookup columns.
- Built passwordless magic-link authentication via EmailVerificationService and ResendEmailSender using Resend's REST API, with fallback LoggingEmailSender for local development.
- Implemented EmailDomainPolicy: validates email format and blocks registrations from disposable email domains and known spam sources using bundled resources (disposable-email-domains.txt, spam-domains.txt, trusted-email-providers.txt); provided .helpers/update-email-blocklists.sh for automated blocklist updates.
- Implemented Google OAuth 2.0 PKCE authentication flow in GoogleOAuthClient: handles code exchange, user profile extraction (email, display name, avatar), and account upsert in UserDirectory.
- Implemented session engine via SessionService: issues cryptographically secure 40-character base62 tokens prefixed with 'hqr_sess_' (~238 bits of entropy), hashes tokens with SHA-256 for database lookup, and tracks user-agent, IP, and activity timestamps.
- Built full API credential lifecycle in CredentialService: creates scoped API keys (hqr_sk_) with lifetimes of 30, 90, 180, 365 days, or never, and personal access tokens (hqr_pat_) with lifetimes of 1, 7, 30, or 90 days.
- Added credential rotation, single-time plaintext secret reveal, credential revocation, and plan limit checks integrated with HalfQR.Billing.
- Provided internal verification route POST /internal/v1/credentials/verify protected with X-HalfQR-Internal-Key and constant-time string comparison (SecretTokens.FixedTimeEquals).

### HalfQR.Billing Service (PayChangu Mobile Money & Plans)

- Implemented billing microservice in microservices/HalfQR.Billing targeting .NET 10 with FileSystemBillingStore and PostgresBillingStore backends managing subscriptions and payments tables.
- Built native Malawi Mobile Money payment integration in PayChanguClient supporting Airtel Money and TNM Mpamba checkout flows with 9-digit telephone normalization and network prefix validation (Airtel '9', TNM '8').
- Implemented webhook receiver POST /api/v1/billing/webhooks/paychangu with mandatory HMAC-SHA256 'Signature' header verification in Production environments, automatically re-verifying payments directly with PayChangu before subscription activation.
- Added background service PaymentTimeoutWorker running every 30 seconds to query PayChangu for unconfirmed mobile charges and expire pending records older than 15 minutes.
- Configured subscription tiers: 'Developer' plan (MWK 15,000 / month, 3 API keys, 5 access tokens, 300 RPM) and 'Business' plan (MWK 45,000 / month, 25 API keys, 25 access tokens, 1,200 RPM), with free tier entitlement fallback.
- Added internal service endpoints GET /internal/v1/users/{userId}/entitlement and GET /internal/v1/users/{userId}/overview secured by InternalHeaders.InternalKey.

### Developer Console & Webapp Interface Architecture

- Built developer console frontend under webapp/src/app/dashboard with dedicated layout shell, responsive sidebar navigation, user session context, and optimistic authentication protection via webapp/src/proxy.ts matching /dashboard/:path*.
- Created CredentialsManager, CredentialsPage, KeyMask, and CopyButton components under webapp/src/components/dashboard for issuing, viewing, copying, rotating, and revoking API keys and Personal Access Tokens.
- Implemented BillingPanel component with real-time entitlement display, plan cards, mobile money checkout dialog with telephone formatting, payment transaction tables with status badges, and manual refresh controls.
- Implemented SessionsPanel in webapp/src/app/dashboard/security/page.tsx displaying active sessions, current browser indicator, user-agent and IP details, and remote session termination.
- Built dedicated authentication flows under webapp/src/app/sign-in and webapp/src/app/sign-up supporting passwordless email verification, Google OAuth 2.0 PKCE, and local development bypass.
- Hardened webapp reverse proxy in webapp/src/app/api/halfqr/[...path]/route.ts: restricted forwarding strictly to /api/v1/qr/* routes, enforced a 1 MB body size cap, allowlisted request headers (accept, content-type) and response headers, and forwarded client IP with HALFQR_PROXY_SECRET.
- Built interactive changelog platform under webapp/src/app/changelog backed by loadReleaseLines() in webapp/src/lib/changelog.ts, dynamically parsing .commits/*.txt files into structured release lines, patch details, and an RSS 2.0 feed at /changelog/rss.xml.

### Compatibility and Deployment Notes

- Database Migrations: PostgresIdentityStore and PostgresBillingStore automatically create their respective PostgreSQL schemas ('identity' and 'billing') along with tables and indexes on first startup; no manual migration scripts required.
- Mandatory Environment Variables: Deployment requires setting POSTGRES_PASSWORD, RABBITMQ_DEFAULT_PASS, REDIS_PASSWORD, HALFQR_INTERNAL_API_KEY, and HALFQR_PROXY_SECRET in .env.
- Identity Base URL & CORS: Webapp requires HALFQR_IDENTITY_BASE_URL (defaults to http://identity:8080 in Docker) to communicate with HalfQR.Identity; PublicApi requires ApiAccess__IdentityBaseUrl.
- PayChangu Webhooks: Public webhook routing for PayChangu requires pointing reverse proxies or tunnels to the Billing service at /api/v1/billing/webhooks/paychangu with PAYCHANGU_WEBHOOK_SECRET configured.
- Backward Compatibility: Anonymous render and draft requests remain functional when HALFQR_REQUIRE_API_KEY is set to false (default); existing static QR codes and rendering parameters remain fully compatible.
